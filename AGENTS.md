# Working on Pi Pocket

In an npm install (inside `node_modules`), read only: to change Pi Pocket, clone the repository.

Pi Pocket is often edited from inside itself, while it runs. [docs/map.md](docs/map.md) says where things are, and [docs/architecture.md](docs/architecture.md) says what they rely on. [docs/self-editing.md](docs/self-editing.md) has the whole of what follows, including how to check a change on a throwaway copy (`node test/serve.ts`). [docs/index.md](docs/index.md) lists every guide. Read [FORK.md](FORK.md) before resolving a merge; it lists every difference from upstream and what a merge must keep. Each page answers one question. The README gives the short list. FORK.md gives the differences and merge rules. docs/features gives the user tour. Link to them instead of restating them. Keep editing safe:

- `web/**` changes reload every open browser right away. Keep the app loadable after each save: a syntax error blanks the screen for everyone, including you. Check with `node --check web/<file>.js` after editing.
- `src/server/extensions/*.ts` changes are reinstalled into the running server. A file that fails to load keeps its previous version and reports the error. Each module default-exports `(host, web) => Extension | Extension[] | void`, possibly async (`web` adds routes and a browser module to the app: [docs/extensions/app.md](docs/extensions/app.md)). Start each module with a `/** … */` comment: its first sentence is the description in the app's Extensions sheet, where the owner can turn modules off (a module that is off is not loaded, even when edited).
- Other `src/server/**` changes need a restart (menu → Restart server). Running work resumes after it, but a tool call cut off mid-run that is not replay-safe comes back as interrupted. Do not restart while your own tool call is running; finish the edit, run `npm run check` and the tests [docs/self-editing.md](docs/self-editing.md#checking-a-change) asks for, then ask the user to restart.
- The owner's drop-in extensions in `~/.pi-pocket/extensions/` load the same way, after the built-in ones, and stay off until the owner turns them on. They import Pi Pocket's packages by name with no link (the resolve hook in `src/server/extension-document-imports.ts`); a `node_modules` link and a `tsconfig.json` there serve editors.
- The vendored provider's own rules are in [src/server/commandcode/README.md](src/server/commandcode/README.md). Read them before editing those files, and keep each change they describe.
- Document kinds in `src/server/docs.ts` are stored data. Do not rename them, or change their scope, history, or fork settings: Pi Durable checks those against what is stored.
- The server is plain TypeScript run by Node's type stripping: only erasable syntax (no enums, no parameter properties, no namespaces). Imports use `.ts` extensions.
- Code style is Oxfmt (`.oxfmtrc.json`: 4 spaces, 100 columns) plus Oxlint's layout rules (`.oxlintrc.json`): braces on every `if` and loop, and a blank line after declarations, around blocks, and before `return` and `throw`. The padding rule runs through `@stylistic/eslint-plugin` as an Oxlint JS plugin; `eslint` stays in devDependencies only as its peer, and is not run. Run `npm run format` after editing. Oxfmt leaves the markup in `html` templates alone, so lay it out by hand the same way: 4 spaces per level, and a tag that runs past 100 columns gets one attribute per line and its children on their own lines. In htm a line break is not a space: break only where there is no space, or between tags, never inside running text.
- Run `npm run check` and `npm run lint` after every change, and the tests [docs/self-editing.md](docs/self-editing.md#checking-a-change) asks for: the feature's own tests, plus the tests of any shared file it touches. `npm test` is slow (over half an hour) and is not the default; run it only for a release or when the owner asks. Say which tests were skipped.
