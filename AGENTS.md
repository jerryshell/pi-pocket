# Working on Pi Pocket

In an npm install (inside `node_modules`), read only: to change Pi Pocket, clone the repository.

Pi Pocket is often edited from inside itself, while it runs. [docs/map.md](docs/map.md) says where things are, and [docs/architecture.md](docs/architecture.md) what they rely on. [docs/self-editing.md](docs/self-editing.md) has the whole of what follows, including how to check a change on a throwaway copy (`node test/serve.ts`); [docs/index.md](docs/index.md) lists every guide. [FORK.md](FORK.md) lists every difference from upstream and what a merge must keep: read it before resolving one. Keep editing safe:

- `web/**` changes reload every open browser right away. Keep the app loadable after each save: a syntax error blanks the screen for everyone, including you. Check with `node --check web/<file>.js` after editing.
- `src/server/extensions/*.ts` changes are reinstalled into the running server. A file that fails to load keeps its previous version and reports the error. Each module default-exports `(host, web) => Extension | Extension[] | void`, possibly async (`web` adds routes and a browser module to the app: [docs/extensions/app.md](docs/extensions/app.md)). Start each module with a `/** … */` comment: its first sentence is the description in the app's Extensions sheet, where the owner can turn modules off (a module that is off is not loaded, even when edited).
- Other `src/server/**` changes need a restart (menu → Restart server). Running work resumes after it, but a tool call cut off mid-run that is not replay-safe comes back as interrupted. Do not restart while your own tool call is running; finish the edit, run `npm run check` and the tests [docs/self-editing.md](docs/self-editing.md#checking-a-change) asks for, then ask the user to restart.
- The owner's drop-in extensions in `~/.pi-pocket/extensions/` load the same way, after the built-in ones, and stay off until the owner turns them on. They import Pi Pocket's packages by name with no link (the resolve hook in `src/server/extension-document-imports.ts`); a `node_modules` link and a `tsconfig.json` there serve editors.
- `src/server/artifacts.ts` is upstream's, with one fork change: a delete also writes a line in the chat, as archiving a session does (`collab.activity`); upstream leaves only Pi's messages and the cards' deleted state. A sync keeps that line, and the assertion in `test/artifact-delete.test.ts` that says the title survives nowhere but there.
- `src/server/session-cleanup.ts` is upstream's, with two fork changes: after a session's files, worktree, and uploads go, its stored rows go too (`PocketApp.purgeStoredData`, `purge.ts`), because Pi Durable has no delete of a conversation; and a session the removed one started loses its `linkedFrom`, which would otherwise point at a session that is gone. A sync keeps both in `#finish` and the removal's commit; `PurgeDoc` stays in `docs.ts` and nothing reads or writes it.
- Document kinds in `src/server/docs.ts` are stored data. Do not rename them, or change their scope, history, or fork settings: Pi Durable checks those against what is stored.
- The server is plain TypeScript run by Node's type stripping: only erasable syntax (no enums, no parameter properties, no namespaces). Imports use `.ts` extensions.
- Code style is Prettier (`.prettierrc.json`: 4 spaces, 100 columns) plus ESLint's layout rules (`eslint.config.js`): braces on every `if` and loop, and a blank line after declarations, around blocks, and before `return` and `throw`. Run `npm run format` after editing. Prettier leaves the markup in `html` templates alone, so lay it out by hand the same way: 4 spaces per level, and a tag that runs past 100 columns gets one attribute per line and its children on their own lines. In htm a line break is not a space: break only where there is no space, or between tags, never inside running text.
- `src/server/commandcode/` is vendored from `patlux/pi-commandcode-provider`, and `generate/` is its 0.7.12 `/alpha/generate` client, which serves the Go plan: Go has no Provider API access, so Command Code answers `403 upgrade_required`. A sync to a newer upstream keeps Go working: do not take upstream's stop at that 403 (0.8.0 onwards drops the client), and keep the fallback in `generate/router.ts` and the tests that pin it. Upstream's `responses-compat.ts` body repairs reach the wire through Pi's `onPayload` here, not through `fetch`, and its `responses-stream.ts` frame repairs ride the transport's `fetch`: keep both wirings when a sync changes them.
- Run `npm run check` and `npm run lint` after every change. Tests are grouped (`npm test`, `npm run test:core`, `npm run test:ui`): run `npm test` before a push or a release, and for a change to a shared entry point; a change inside one feature runs that feature's own tests (and its UI tests). [docs/self-editing.md](docs/self-editing.md#checking-a-change) lists the shared entry points and the area-to-test table. The full suite takes over half an hour: a patch release merge (`v0.28.1` → `v0.28.2`) runs only the test files the release touches (`git diff --name-only v0.28.1 v0.28.2 -- test/`), and a small upstream sync of the vendored `src/server/commandcode/` provider runs `test/commandcode*.test.ts`. Say which tests you skipped.
